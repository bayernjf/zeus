# 记忆与自进化：与 Zeus 的结合方案（草案）

> **性质**：基于 [research-memory-self-evolution.md](research-memory-self-evolution.md)（两轮外部咨询问答的整理稿）给出的**结合分析**。设计待裁定，**未开工**；文中"已落地"的部分可在库内代码/文档核对，"缺口"与"候选"是判断而非承诺。
>
> **一句话结论**：zeus 不该去做"又一个记住你的记忆产品"，而该把这两件事落在它已有的结构上——**记忆做成「可验证的组织记忆」（每条事实能追溯、能验完整性、能擦除且留痕），自进化做成「决策参数的可审计写回」（失败 → 归因 → 改变下一次派发）**。这两件事外部建议都只讲了一半，且都是 zeus 已经铺好地基、只差闭环的部分。

## 二、zeus 独有的两个落点（外部建议没有的）

外部建议的 L1 闭环是**单 Agent 视角**："这次任务失败 → 我反思 → 我下次记得"。在 zeus 里，同一意图会扇出给多个执行 Agent，因此有两件事是个人助手做不到的：

### 2.1 同题可比数据 → 可靠度可量化

同一类技能被多个执行 Agent 执行，就有**同一任务的可比结果**。可靠度（`1 - failureRate`）已经是现成量，且已接入两处：

- **记忆侧**：consolidate 时按可靠度加权合并事实（作者自报置信度从不单独采信）；
- **决策侧**：饱和分流时按 `可靠度 × 延迟 p50` 评分重排候选（deferred #9 机制已落地，阈值待 ≥3 真实执行 Agent 压测）。

也就是说，"**从失败中学习**"在本项目里已经有了一个可量化的落点：**不是让某个 Agent 记住教训，而是让派发决策下次更挑对人**。这条路的护城河来自跨执行 Agent 的历史对比数据——个人助手拿不到这个数据面。

### 2.2 写回面 = 决策参数，而不是提示词

外部建议明确警告"自进化不能失控，Agent 自改 prompt 有风险，L1 只看不改"。本项目的口径更进一步：**连"改"都不必做，改的是纯函数里的参数与顺序**：

| 写回对象 | 已有形状 | 写回形态 |
|---|---|---|
| 选靶 | `selectCandidates` / `selectTargets`（点名 > 自动选靶 > 信任/能力面过滤） | 评分权重 / 饱和门限，纯函数可单测 |
| 失败恢复 | `recoverChain` 四步序（重试 → 换将 → 降级 → 升级） | 哪一步在什么条件下更优先 |
| 记忆召回 | `assembleBranchContext` + `contextOptions` | 召回偏好与裁剪口径（相关性闸已存在、默认关闭） |
| 终止 | 步数预算 + 连续失败熔断（S4） | 阈值 |

这四个都是**确定性、可审计、可回滚**的（每次写回落审计与快照，重启可恢复），完全落在设计约束 2（每个概念必须可执行、可验证、可恢复）之内——而"模型自改提示词"落不进这个约束。

### 2.3 记忆的定位差异：组织记忆 + 个人记忆两面

外部建议默认"一个 Agent 记住一个用户"。本项目是**多 Agent 运行时**，记忆有两面且在数据域上隔离：

- **个人域**：用户自己的目录，正文默认不出机器（设计约束 1）；
- **组织域**：多个执行 Agent 的产出合并成共享事实，带 provenance、可靠度、矛盾升级与责任链。

由此推出的差异化不是"记得更多"，而是**可验证的记忆**：每条事实能追到来源事件（`provenance`）、能验不变量（`verifyMemoryState`）、能被擦除且擦除留 tombstone 供治理回放。这三条外部建议都没提，而它们恰好是"数据主权在用户"这个约束下最难被复制的部分。

## 三、真正的缺口（四项，各带触发条件）

| 缺口 | 现状 | 为什么现在不做 / 做的条件 |
|---|---|---|
| **① 模型驱动的复盘**（闭环第 2 步） | 归因是确定性聚合（分类计数），没有"用模型生成结构化复盘 + 经验卡" | 需先裁定**是否允许外部模型参与**（正文出域 vs `dataPolicy` 口径）；允许后才可开工 |
| **② 写回面**（闭环第 3/5 步） | 未做；#40 只读归因已落地并标 `writebackCandidate` | 挂 deferred **#40** 触发条件：首个真实执行 Agent 长期运行、有可统计的失败样本分布（同 #9 的 ≥3 真实 Agent 口径）。mock 的失败模式是编的，会把猜测锁成猜测 |
| **③ 记忆 producer 只产 claim** | `MemoryKind` 四类里 observation / action / decision 未接 | 需要真实负载里"哪些执行 Agent 的哪种回报值得入记忆"这一分布；与 ② 同触发条件 |
| **④ 检索规模化** | P0 是文件系统扫描 | deferred **#10**：单 Realm > 2 万文件 / P50 > 500ms / 语义检索成为明确需求 |

另有两条**非缺口但可能被误当缺口**的：遗忘"淡化"（按重要性衰减）——本项目走的是显式遗忘 + 用户可擦除，刻意不做隐式衰减（记错比记不住更糟）；长期画像层——已以编制/席位/认证形态存在，不需要再建一层"Profile"。

## 四、三条硬口径（能抄什么、不能抄什么）

| 外部建议 | 本项目口径 | 理由 |
|---|---|---|
| Pinecone / Mem0 / Zep 等托管记忆服务 | **不做**；候选是**自持** pgvector（同一台机器），且 embedder 保持本地 | 把用户正文交给第三方托管，违反设计约束 1（数据主权在用户）；也正是企业形态裁定要避免的失败模式 |
| 用强模型（Opus 级）做反思 | 只能走：本地 / 自持模型，或**显式授权后的外部调用**并审计留痕 | 把任务内容交出去 = 正文出域；`dataPolicy` 收缩契约要求按 policy × origin 判档，跨域需显式、签名、一次性授权 |
| Agent 自改 prompt / 工作流（L3） | **不做**；本项目的写回只改 §2.2 那四个纯函数参数 | 违反设计约束 2（可执行、可验证、可恢复）与"写回必须可审计、可吊销"；改崩了要能回退到已知状态 |

一句话：**外部建议的技术选型可以抄，部署位置不能抄；自进化的对象（提示词）不能抄，落点（决策参数）可以抄。**

## 六、需要你裁定的事项

1. **外部模型能否参与复盘？**（决定 S1 能不能开工）——本地/自持模型，还是显式授权后的外部调用，还是先只做纯规则复盘（能力最弱但不违约束）。
2. **写回的默认强度**：写回只改排序权重（安全、可回滚），还是也允许改熔断/预算阈值（影响终止行为，风险更高）。
3. **经验卡是否进用户目录？** 进 = 可备份可继承（与传承愿景一致），不进 = 只在内核状态文件里（备份清单已覆盖，但用户看不见）。这决定它算"用户数据"还是"运行状态"。
4. **要不要为这件事立一个新的 deferred 条目**（复盘原语的形状 + 写回面），还是继续挂在 deferred **#40** 名下。

## 七、明确不做的

- **模型层记忆与自进化**（持续学习、不遗忘、自我改进架构、RL）——不在本项目射程。
- **隐式记忆衰减**——用户可擦除 + 显式遗忘已足够；隐式淡化会让用户失去"我到底让它记住了什么"的控制权。
- **把记忆做成对外服务**——记忆能力以本项目既有通道（MCP / Skill / A2A）供他人接入，不新增第四条旁路。

## 八、数据来源基座（本地目录）= 记录源，与记忆六面、文档技术栈的对应关系

> 本节回答一个定位问题：用户提供给 Zeus 的接口（本地目录 / 数据库）在记忆体系里处什么位置。结论——**它是 raw data（原始数据层），是记忆的主要来源、也是长期记忆的原材料；同时也是记录源（Source of Record），即记忆的权威真相所在地**。文档（research 稿 §2.3/2.4/3.4/5/6）给的通用技术只是它之上、且必须自持的衍生索引。本节为新增定位，不改动上文结论与草案。

### 8.1 用户提供的本地目录 / 数据库 = raw data 原始数据层

用户给定的数据（本地文件夹、数据库等）是 **raw data（原始数据层）**：它是记忆的主要来源，也是「长期记忆」的原材料与原始数据。记忆不是凭空生成的，它的根就在用户提供的这份原始数据上；长期记忆是从 raw data 里抽取、结构化出来的衍生产物。

记忆层是建在该 raw data 之上的、带时间戳与溯源的**衍生层**，而不是另起炉灶的副本：

- **raw data 存正文（body）**：主权在用户、默认不出本机（设计约束 1）；
- **记忆存衍生物**：抽取的事实 + 指向 raw data 的路径指针 + 内容哈希 + 变更事件，轻量、可备份、可与 raw data 一起恢复。

由此，记忆的「重要来源就是用户给定的这份数据」被落实为机制：raw data 一动，记忆就有迹可循；raw data 恢复，记忆可重新验真。

#### 8.1.1 与业界技术方案的关系：概念一致，部署更严

- **概念层一致**：业界三层记忆（research 稿 §2.1）中，外部文档 / 数据库正是中期记忆（RAG 检索语料）与长期记忆（知识图谱 / 结构化 Profile 的抽取源）的共同原始数据。本项目的「raw data 是长期记忆的原始数据」判断与业界 RAG / 知识库产品的底层假设完全吻合。
- **部署层更严**：业界多数 RAG 产品会把 raw data **复制进向量库 / 知识库**（正文进向量存储，记忆自带副本）；本项目出于数据主权（约束 1）**不复制正文**，记忆只存衍生物 + 路径指针，raw data 正文始终留在源（目录 / 数据库）。即：来源判断与业界一致，「记忆是否复制 raw data 正文」是 Zeus 出于主权做的不同选择。

### 8.2 三个连接锚点（目录 ↔ 记忆六面）

| 锚点 | 作用 | 对应六面 |
|---|---|---|
| 路径指针（path ref + offset/range） | 每条 fact/event 指向目录里的源文件与片段；recall 返回指针 + 摘要，不搬运正文 | `facts` / `recall` |
| 内容哈希（content hash） | 目录文件内容的哈希是 `integrity` 面的基准，记忆自证未与源漂移 | `integrity` |
| 变更事件流（change event stream） | 目录 create/modify/delete 驱动 `events`；目录变更推翻旧 fact 触发 `retractions` | `events` / `retractions` |

### 8.3 文档技术栈 ↔ Zeus 六面 的映射

research 文档给的是**行业通用参考技术**（含 Mem0 / Zep / Pinecone 等），不是 Zeus 实现。对应关系与采用口径如下：

| 文档里的参考技术 | 通用定位 | Zeus 对应部件 | 采用口径 |
|---|---|---|---|
| 向量库 + RAG / 混合检索（pgvector / Qdrant…） | 中期记忆：语义召回 | `src/memory/recall.ts`（BM25 + 本地 embedder） | ✅ 自持 pgvector（同机），embedder 本地；**不做** Pinecone/Mem0/Zep 托管（约束 1，见 §四） |
| 结构化 Profile / 知识图谱 | 长期记忆：人/事/物/关系/偏好 | `facts` + 编制（部门/席位/必备技能/认证） | ✅ 已以编制形态存在，不另建 Profile 层 |
| 记忆提取（模型抽取结构化信息） | 把对话/文档抽成事实 | `src/memory/producer.ts`（claim 事件 → consolidate） | ✅ 已有（只产 claim，observation/action/decision 待接，见 §三③） |
| 记忆更新 / 矛盾处理 | 合并/修正/遗忘 | 可靠度加权 + `disputed` 升级 + `retractFacts`/`forgetSubject` | ✅ 已有（显式遗忘，无隐式淡化，见 §三末） |
| 记忆审计 / 可解释可编辑 | 用户可见可改 | 六面只读 + 监督台记忆视图 + 事实表 | ✅ 已有 |
| Reflexion / 经验库 + RAG | 自进化 L1 闭环 | 只读失败归因 `failure-attribution.ts` + 写回面（§2.2） | 🟡 半有 / ❌ 缺（见 §三①②） |
| PostgreSQL + pgvector + 对象存储 | 存储层 | 内核状态文件 + Vault 备份 | ✅ 自持；对象存储仅作备份目标，不托管正文 |

### 8.4 三层关系（一图）

```
用户目录 (SoR, 主权, 正文)          ← 记忆的重要来源 / 记录源
   │  change event stream + content hash
   ▼
记忆六面 (衍生层: 指针 + 事实 + 溯源)   ← events/facts/replay/recall/retractions/integrity
   │  语义召回由自持 pgvector 支撑 (recall 面)
   ▼
存储/备份 (内核状态文件 + Vault)       ← 与目录一起备份恢复, 正文不出本机
```

一句话：**目录是记录源（正文归用户），六面是它的带溯源时间视图，文档里的 pgvector/RAG 等通用技术只是六面之上、且必须自持的衍生索引**——部署位置不能抄托管方案（§四）。
