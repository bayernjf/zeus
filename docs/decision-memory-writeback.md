>
> **为什么现在只能裁定、不能写码**：S2 写回面在 design 文档 §三② 挂了两个闸门——① 本页 S1 裁定（外部模型能否参与复盘）；② deferred #40 触发条件（首个真实执行 Agent 长期运行、有可统计失败样本分布）。#40 当前不满足（无真实 Agent 在线，E10.2 门面真机部署未做），故 S2 的代码要在首个真实 Agent 长期运行后才有可统计样本。先裁定的价值是**把设计契约定死**，裁定后 S1 的复盘原语形状即可先定（不落码也可定契约），代码等 #40 触发。

## 待裁定清单

### D1 — 外部模型能否参与复盘？（S1，唯一策略决定）

闭环第 2 步「生成反思报告」目前是确定性聚合（`src/reflection/failure-attribution.ts`，只标 `writebackCandidate`，不是模型复盘）。D1 决定要不要、以及怎么让模型参与。

| 选项 | 说明 | 约束影响 |
|---|---|---|
| **A 本地 / 自持模型** | 复盘用本机或自持模型，正文不出域 | 最合规；依赖自持模型可用性 |
| **B 显式授权后的外部调用** | 任务内容交外部模型前需显式授权，并审计留痕 | 正文出域，须按 `dataPolicy` × origin 判档、跨域显式签名一次性授权 |
| **C 先只做纯规则复盘** | 不引入模型，只做确定性聚合 + 经验卡（能力最弱但不违约束） | 零约束风险，可作为首个落地形态 |

**推荐默认**：**C 起步**，A/B 作为后续升级路径。理由：C 不违任何设计约束、不依赖真实模型可用性，且能在 #40 触发前先把「经验卡 shape + 写回面」的机械层（apply/revert/audit）落稳；A/B 的模型复盘原语形状可先定契约、等授权/自持模型到位再接。

### D2 — 写回的默认强度

写回对象见 design 文档 §2.2 四个纯函数参数（选靶评分权重 / 恢复步骤优先序 / 召回偏好 / 终止阈值）。

| 选项 | 说明 | 风险 |
|---|---|---|
| **只改排序权重**（选靶、恢复、召回偏好） | 安全、可回滚，不改终止行为 | 低 |
| **也允许改熔断 / 预算阈值** | 影响终止行为 | 高（终止行为变化需更强审计） |

**推荐默认**：**只改排序权重**；阈值改动单独成闸门、默认关闭，待 #9 真实压测后再开。

### D3 — 经验卡是否进用户目录

| 选项 | 说明 | 与愿景关系 |
|---|---|---|
| **进用户目录** | 经验卡算用户数据，可备份、可继承 | 与「用户数字记忆的备份与继承」愿景一致 |
| **不进，只在内核状态文件** | 备份清单已覆盖，但用户看不见 | 用户无感，传承弱 |

**推荐默认**：**进用户目录**（算用户数据）。与 Vault 备份 + 传承协议天然对齐；经验卡因此走和日记 / 每日记录同一条主权路径。

### D4 — 是否立新的 deferred 条目

| 选项 | 说明 |
|---|---|
| **立新条目** | 把「复盘原语形状」与「写回面」从 deferred #40 拆出；#40 保留为「真实样本触发」单一职责 |
| **继续挂 #40** | 不拆，复盘与写回都挂在 #40 名下 |

**推荐默认**：**立新条目**——「复盘原语」与「写回面」是两个不同性质的待办（前者是契约/原语，后者是接线/审计），混在 #40 下会让 #40 的触发条件语义变糊。

## 裁定后的下一步

1. D1=C/A/B 决定后 → 定 S1 复盘原语 shape（经验卡结构 + 入库口径），可先落契约不落码；
2. D2/D3/D4 决定后 → S2 写回面的机械层（apply 参数 / revert / audit / snapshot）可在 #40 触发前先落（用合成样本验证、明确标注非真实负载）；
3. #40 触发（首个真实 Agent 长期运行、有失败样本分布）→ S2 接真实负载、S3 producer 扩事件类型。
