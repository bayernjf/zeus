## 1. 背景与问题

- 个人用户：工作提效之外，记忆与数据散落在各 SaaS，**无主权、不可备份、不可传承**；情绪层面缺少"被记住、被保护"的长期载体。
- 企业用户：Agent 能力以点状工具存在，新员工上岗成本高，知识随人流失；缺少一个员工可驾驶、可监督、且对业务结果负责的多 Agent 协作层。
- 供给侧：已有产品矩阵（agent-world、job-agent、agent-dev、pr-helper、atlas、loom；展示站 bayjf）各自独立，用户被迫面对一整组工具，产品之间存在隔阂。

## 2. 产品目标与非目标

### 2.1 目标（v1 周期）

1. 用户给一个目录即可用：目录即数据库，先连接、经接口访问，备份为第一公民。
2. 用户只面对 Zeus 一扇门：矩阵产品以封臣身份向 Zeus 效忠，星型编排、可吊销、名册可验。
3. 个人情感闭环：藏宝图备份真实可恢复，日记承载记忆，传承路径可验证。
4. 企业组织闭环：员工以驾驶员身份上岗，Mentor 带业务，A2A 承接流程，全程审计。

### 2.2 非目标（Non-goals）

- 不自造 MCP/A2A 之外的私有封闭协议；Zeus v1 不做 A2A server（发起方永远是 Zeus/驾驶员）。
- Realm 不做独立 HTTP API（对外唯一传输为 MCP）。
- 不做封臣之间的 P2P 直连；不做企业→个人数据域的任何互通（无例外）。
- 传承的法律框架与企业计费模型不在 v1 实施（deferred #3/#4）。

## 3. 用户与核心场景

| 用户 | 核心场景 | 情感/商业承诺 |
|---|---|---|
| 个人用户 | 接入目录 → 组 Agent 班子 → 日记/藏宝图 → 备份与恢复 → 可选传承 | 被记住、被保护、不被绑架 |
| 员工（驾驶员） | 上岗即被 Mentor 带教；以监督/拍板方式驱动 Agent 团队 | 港湾：有导师、有归属 |
| 企业采购方 | Zeus 作为虚拟部门承接流程；权限可审计、知识不流失 | 人效、留存、合规 |

## 4. 需求拆解（Epic → 需求 → 验收）

优先级：P0 = v1 必须；P1 = v1.x；P2/P3 = 后续版本。

### E1. Realm 数据域（数据主权底座）

| ID | 需求 | 优先级 | 状态 | 验收标准 |
|---|---|---|---|---|
| E1.1 | connect 目录并生成 manifest（确定性 realmId、类型固定 personal/enterprise） | P0 | ✅ | realpath 派生 id 且幂等；未 connect 一律拒绝读写；类型一经 connect 不可变 |
| E1.2 | 扫描式 search + read | P0 | ✅ | 文本白名单/隐藏与依赖目录剪枝/1MiB 上限/symlink 拒绝；路径穿越路径段+realpath 双检拒绝 |
| E1.3 | contentDigest 基线 | P0 | ✅ | 全量内容指纹稳定（顺序无关），供备份与漂移对账 |
| E1.4 | Realm MCP server 暴露（streamable HTTP + 鉴权） | P1 | 🚧 stdio | 只读 stdio 壳已落地（resources 映射，root/connect 不出协议）；正式启动触发条件：read-realm 封臣出现 |
| E1.5 | write 与驾驶员授权凭证 | P1 | ⬜ | personal 默认可写；enterprise 写必须带授权凭证，全程审计 |

## 6. 成功指标（待基线）

- 信任：藏宝图恢复演练成功率（目标 100%）；数据事故数（目标 0）。
- 个人：周活留存；备份覆盖率；Diary/Map 的情感闭环验证用户数。
- 企业：新员工上岗耗时；流程 A2A 承接比例；知识可检索率。
- 联邦：在册封臣数；吊销生效延迟（目标实时）；SLA 受理违约率。
