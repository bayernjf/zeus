# 决策记录保留：出窗归档（deferred #42 设计稿）

状态：**设计稿**（非实施）；实现待触发条件（见 §5）。
关联：deferred #42、#13（备份清单）、#40（反思闭环）、#41（隔离实例形态）。

## 1. 问题

内核长跑之后仍在线性增长的，只剩用户自己的决策记录：意图结果与原始请求
（实测字节占比 75% / 25%，合计 ≈2,074B/条）、监督台里已裁决的条目、memory 事件。
派生观测面（分支历史）已于 2026-10-06 封顶并挪到读路径（audit-2026-09.md §13.4），
这些没有。

状态文件每次退出全量重写、每次启动全量解析，随长跑线性增长。外推数字
（只当算术看，不当实测）：3,000 条 ≈ 6.2MB 状态文件 + ≈180MiB RSS。

## 2. 为什么不能"顺手封顶"

删掉一条已存意图会同时删掉三样承诺：

1. **intentId 幂等重放**——重提交将重新派发而不是返回旧结果；对 execute 意图
   等于把一次外部写再做一遍。
2. **`GET /api/intents/:id/replay` 的可追溯性**——"可复核"是产品承诺，不是缓存命中。
3. **已裁决升级项所指向的意图**——approve-resume 依赖 `findIntentForBranchRun`
   在存留集合里找。

这些是用户数据与承诺，不是可丢弃的中间结果。

## 3. 三条候选与代价

| 方案 | 行为 | 代价 |
| --- | --- | --- |
| A 不删（现状） | 无限增长 | 状态文件全量重写/解析成本随长跑线性上升 |
| B 按条数/时间封顶 | 保留被 open 升级项引用与曾被人裁决的条目 | 幂等承诺从"永久"降级为"窗口内"；PRD、README、审计措辞三处改口 |
| **C 出窗归档（倾向）** | 出窗意图写入只读归档，状态文件不再携带，replay 从归档读 | 新增归档读取面 + 归档纳入备份清单；工程量最大，但**唯一不改承诺**的一条 |

## 4. 方案 C 设计

### 4.1 归档形态

- 文件：`<stateDir>/intent-archive.jsonl`，JSONL 追加写；每条一条出窗意图记录：
  `intentId`、`ts`（ISO-8601 UTC）、`request`（原始派发输入）、`result`（最终结果）、
  `status`（终态）、`references`（被升级项引用的意图集合，如有）。
- 只读语义：归档一经写入不再修改（append-only）；出窗记录不随状态文件携带。
- 幂等：归档条目以 `intentId` 为主键，写入前查重（防重放写）。

### 4.2 出窗判定与默认值

- 默认 A（不归档），直到触发条件满足（§5）才启用出窗。
- 启用后的出窗窗口：按条数上限（如 1,000 条）与时间窗（如 30 天）双条件，
  先到先出；**被 open 升级项引用或曾被裁决的条目不出窗**（与 B 的保留集一致）。
- 出窗是移动不是复制：条目从状态文件移入归档，同一意图不会两处并存。

### 4.3 读取面

- `GET /api/intents/:id/replay`：先查状态文件，未命中查归档；归档命中返回
  与存留条目同构的回放（时间线从归档记录重建，缺失派生事件时返回 501 而非
  半条时间线——诚实降级）。
- **幂等重放**：重提交同 `intentId` → 先查状态、再查归档；归档命中返回旧结果，
  不重新派发（execute 意图保证外部写只发生一次）。
- **findIntentForBranchRun**：状态集合 + 归档联合查找，语义不变。

### 4.4 备份清单纳入（#13 联动）

- 归档文件进入备份清单；备份恢复时归档与状态文件同目录同时恢复，保证
  "删记录不会缩小可恢复面"的约束不被破坏。
- 归档纳入 E5.3 的原子保存路径（与状态文件同事务批次，避免"状态已保存、
  归档丢失"的窗口）。

### 4.5 B 开关口径（用户显式开启省空间）

- 若用户显式选择"旧决策不需要留、机器空间优先"，B 升为默认：出窗条目直接
  删除（不写归档），并在 PRD、README、审计措辞三处同步改口幂等承诺为
  "窗口内"，避免文档承诺实现不再兑现的东西。
- B 模式下 `GET /api/intents/:id/replay` 对已删除条目返回 404（含原因字段
  `archived:false, evicted:true`）。

### 4.6 联动

- **#40**：反思闭环读历史决策——归档是历史决策的只读数据源，归因摘要可
  以把归档条目的失败 reason 并入聚合（只读，不回写）。
- **#41**：隔离实例形态下每个实例历史独立，出窗窗口可按实例配置；同实例
  多租户下"谁的历史留多久"变成租户属性（本稿不展开，待 #41 裁定后细化）。

## 5. 触发条件（实现起点）

出现第一个连续运行 ≥2 周且有真实使用的实例，或实测到：

- 状态文件 > 50MB；或
- 重启恢复 > 2s；或
- `GET /api/intents/:id` 因集合膨胀而变慢。

满足其一即启动 §4 实施；在此之前维持默认 A，不做半程改造。

## 6. 验收口径（实施时）

1. 出窗后状态文件体积回落到窗口内规模，幂等重放对归档意图返回旧结果（零出站）。
2. `GET /api/intents/:id/replay` 对归档意图可追溯（或明确 501 降级，不返回半条时间线）。
3. 备份清单包含归档文件；恢复后归档与状态一致。
4. B 开关下三处文档改口与行为一致。
