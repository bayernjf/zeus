# T-M7-05 repeatable org-level e2e evidence

This bundle is generated by `scripts/e2e-m7.mjs` (`npm run e2e:m7`). It captures one
**repeatable, deterministic, replayable** org-level closed loop over **real** processes:

- a real **agent-world** pnpm-monorepo server (`WORKER=fake` replaces *only* model
  calls — the graph engine, gates, human halts, events and artifacts genuinely run),
  freshly bootstrapped first account;
- a real **zeus** HTTP server (SQLite, `taskExecutor=agent-world`, sqlite action
  store, Ed25519-signed JSONL decision audit chain).

`WORKER=fake` output is **not** real business data; it proves the graph/routing/halt/
approval/audit plumbing. Production acceptance (real cloud secret management,
domain/TLS, real shop/sandbox credentials, real notification webhooks, live-operation
period) remains externally blocked — see handoff.md for the GATE-M7 wording.

## How to run

```bash
# agent-world requires Node 24
eval "$(fnm env)" && fnm use 24.20.0
cd zeus
npm run build            # dist/http/serve.js + dist/core/audit/* must be current
npm run e2e:m7
```

Ports are picked dynamically (the well-known one-off ports are avoided). A throwaway
Ed25519 RSK is generated per run into a gitignored scratch dir; the login credential
travels only through `ZEUS_SECRET_AGENT_WORLD_LOGIN` / SecretBackend — **no secret is
written into this bundle or git**. Every spawned process and port is freed on exit.

## What it asserts (see `manifest.json.assertions`)

| Assertion | Meaning |
|---|---|
| `contentD0Autonomous` | D0 content task completes with no human (real runId, 8 artifacts). |
| `listingD3HaltApproveResume` | D3 listing halts at the human node, then completes only after an external ops-lead approve. |
| `afterSalesD2HaltApproveResume` | D2 after-sales halts, approves, completes; notify hits the local webhook receiver. |
| `failClosedNoToolsSopIncompatible` | A no-tools position cannot be dispatched: 409 `SOP_INCOMPATIBLE`, task stays `pending`, zero channel calls. |
| `failClosedUnknownWorkflowSopMissing` | An uncatalogued workflow is rejected: 409 `SOP_MISSING`, zero channel calls. |
| `failClosedD2onD3ParksThenUnlocks` | A D2-scoped position on the D3 listing workflow **parks** at the D3 checkpoint (cannot self-authorize the publish); it completes only after an external D3 approval unlocks it. |
| `idempotentSameKeySameRun` | Re-creating a task with the same idempotency key returns the same task and the **same** agent-world runId — no second graph run. |
| `auditChainVerified` | The Ed25519 JSONL decision chain verifies end-to-end (`audit-verify.json`). |
| `tamperDetected` | A byte-mutated copy of the chain **fails** verification (negative control). |
| `webhookReceived` | The after-sales/listing notify actually POSTed to a real HTTP receiver (3 captures). |

## Files

- `manifest.json` — machine-readable run summary + assertion booleans.
- `runs.json` — per-position task results, agent-world runIds, halted timelines (`.run.status`, `haltedNodeId`).
- `decisions.json` — the D2/D3 decision records (grade, status, approver).
- `tasks.json` — final state of every task including the fail-closed ones.
- `fail-closed.json` — the three fail-closed outcomes and the missing-tools reason.
- `idempotency.json` — same-key → same-id → same-runId proof.
- `audit-verify.json` — Ed25519 chain verification result + tamper control.
- `webhook-captures.json` — raw POST bodies the local receiver captured.

## Re-verifying

Re-run `npm run e2e:m7`; it regenerates this bundle in place. The audit-chain signature
is verified inside the script with the public half of the per-run RSK, and the tamper
control must fail — if any assertion prints `FAIL`, the process exits non-zero and
cleans up its processes.
